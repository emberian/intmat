# A runnable predictive-program baseline

This is an authored control scaffold and affordance assay, **not the intended general agent architecture**. The next architecture shares a trainable recurrent representation across continuous action and prediction heads. A finite menu and a separately trained tiny predictor must not become a permanent decomposition just because this first version is easy to inspect.

`NativePredictivePrograms` observes support-weighted local raw, soluble and catalyst concentrations for both species, each through x/(1+x). It never reads source phase, future fields or other residents' private state. Per-resident fast/slow raw filters (.4/2) and a five-feature linear model predict the next observed raw receptor values. Every .2 model-time: observe; settle the preceding stamped target; propose normalized predictor updates; pay actual coefficient turnover from the native battery/work ledger; retain only affordable writes; update memory; forecast; inspect the program state. New IDs reset the model and initialize filters from their actual first observation. An off-cadence newborn forecasts the next actual global observation tick. Hidden/filter arithmetic follows the existing native controller convention; learned coefficient writes cost .001 per absolute displacement. No claim is made that all computation is thermodynamically priced.

The authored repertoire has Harvest, Build A, Build B and Balanced Build. Build uses investment .3 and allocation .9/.1/.5 for .4, followed by a .8 harvest tail. Harvest requests zero construction. Reserve stays .02 in every mode to avoid changing primitive precursor priority while diagnosing construction. The native metabolism, balanced precursor consumption, affordable secretion, spatial deposition and all downstream physics remain authoritative. The wrapper replaces requests through the shared `dh_set_requests!`; it does not fabricate deposition.

Selection compares an approximate balanced-store-capacity gain after construction debit. Estimated conversion uses native catalytic saturation/decay, an explicit capture prior .25 and horizon2, capped by native uptake throughput and storage headroom. This is an uncertain authored planning model, not an observed action counterfactual. Neither local support averaging nor the capture prior solves the actual reaction/diffusion/uptake system. The zero-decay limit is handled explicitly. Forecasts describe observed on-policy availability, not passive supply separated from residents' effects.

## Actual eight-time run

The frozen16³ three-arm run uses the existing finite-funded slow-growth recipe. Both forecast and current/persistence planners learn the same predictor and pay the same write costs; only the planner's forecast/current input selection differs. The third arm forces the same Balanced Build/dwell/tail schedule. Every recorded observation is an actual completed step; sensor and prediction stamps distinguish start-of-step sensing from completion. Missing newborn observations remain null. No frame interpolation supplies evidence.

Forecast and persistence arms selected exactly the same actions and trajectories in this run. Both end with46 residents,22 births, total funded catalyst .01409767 and predictor work .001037914. Matched stamped forecast-coordinate MSE is2.14696e−5 versus persistence2.45381e−5, a modest prediction improvement without action benefit. The fixed Balanced program ends with26 residents,2 births and funded catalyst2.493355; it is a different material trajectory, not automatically a better objective value. The sparse construction in the planner arms is consistent with its conservative capture/cost model. No additional gain tuning or long run is being used to manufacture a success.

The source epoch and complete records remain under `outputs/predictive-programs-epoch-v2` and `outputs/predictive-programs-baseline-v2`. The earlier v1 source-stage failure is preserved; it lacked an existing script dependency and never produced a simulation. Compact public metrics are in `docs/figures/predictive-programs-baseline.json`. The generic program observatory presents actual sensing, predictions, phases, requests and funded work.

## Composition and native execution

Twenty-one focused CPU checks cover transforms, the zero-decay limit, invalid clocks/options, actual build→harvest transitions, paid prediction, exact partial continuation, unaffordable write atomicity, identity reset, next observation targets, and material/potential closure. The separate two-time CPU/AMD fixture uses near-division founders and forced Build A to cover24 actual births,432 paid predictor updates and1.425629 funded catalyst. Maximum compared floating difference is1.1921e−7; integer private clocks/IDs match exactly and ledger residual is1.3767e−14. This gate confirms native composition; it is not a learning-benefit test or a GPU fork claim.

The baseline uses the original frozen native source pin. A subsequent default-no-op controller override seam for the general recurrent agent is a separate change and must not be retroactively attributed to these results.
