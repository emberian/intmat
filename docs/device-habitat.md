# Resident constructive device ecology

`DeviceConstructiveEcology` composes the Julia `DeviceCellular` process with paid, inherited catalyst secretion, a separate raw-feedstock reservoir, catalytic soluble-food release, reversible finite-capacity sorption, and catalyst-dependent permeability. Simulation stages remain device resident; explicit snapshots/audits/checkpoints transfer arrays to the host. The current implementation supports CPU KernelAbstractions and AMDGPU. Its local Float64 conservative rounding and sorption solver intentionally exclude Metal.

The controller senses the same frozen external state for every cell. Construction requests enter respiration planning before catabolism; after maintenance, growth and both catalyst requests share precursor and work limits. Every unit costs half A and half B. Only representable catalyst deposits are paid; undelivered requests remain intracellular. Construction occurs before death handling. New daughters inherit their surviving parent's readout through slot reuse. Cumulative slot ledgers retain physical history.

Raw feedstock has separate diffusion/source accounting and cannot be directly eaten. Catalytic release debits actual raw withdrawal, credits actual soluble delivery, and records unrepresentable residue and downhill potential as inert material and heat. Catalyst decay releases waste. Sorption uses the closed-form local reversible law; capacity collapse releases supported material or explicitly retains unreceivable excess as inert. Permeability combines the freshly rebuilt body/background permeability with the current matrix factor. The wrapper advances the global clock once and rejects duplicate scheduling of borrowed cells.

## Actual AMD gate, 2026-10-15

The [machine-readable result](device-habitat-results.json) records a bounded 20-step CPU/AMD comparison on Radeon RX 6750 XT, Julia 1.12.4, AMDGPU 2.8.0, with process-local device compiler optimization level 1. Two cells became four, with positive secretion, raw-food conversion and bound food, and reduced permeability. Maximum compared array error was `1.1920929e-7`; material residual was `5.0061e-8` against total `44.4800015`, and potential residual was `4.6292e-7` against `242.720009`. GPU checkpoint restoration was exact. The 24.65 seconds include compilation and both reference/device loops: they are not a throughput measurement or a large-ecosystem result.

That successful source is preserved at `/othersys/tmp/intmat-probe-20261014/device-habitat-v2`, with its isolated environment, result and logs. The result pins all sources and runtime files. Its first startup attempt exposed a bulk-upload dispatch issue for reinterpreted catalyst bits; materializing the host UInt32 array fixed it without scalar GPU indexing. Subsequent source revisions promote finite free-plus-bound totals and permeability resistance to Float64 before arithmetic, harden strict restore and generic failure preflight, and consume the shared dense/axis support iterator. These revisions require their own AMD gate before attributing the recorded GPU result to them. Imported bound food undergoes compulsory capacity collapse after precision conversion, with actual soluble release and explicit retained residue/heat; no mass is clipped away.

The existing hbox runtime setup is described in [hbox-runtime.md](hbox-runtime.md). With GPU ownership granted, run `scripts/probe_device_habitat.jl RESULT.json` through `scripts/device_cellular_setup.jl`'s configured AMD environment, `DEVICE_BACKEND=amd DEVICE_AMD_OPTLEVEL=1`, two host threads, GC/BLAS one thread, and the documented 8 GiB `swarm-build` limit. The probe uses `scripts/device_habitat_fixture.jl`; CPU mode is `DEVICE_BACKEND=cpu`.

## Checks and remaining scaling work

The final CPU gates passed 13,552 sorption assertions and 33 coupled/budget/lifecycle assertions, plus a separate three-check inventory/Arena/extreme-permeability gate. Focused tests cover contended conservative atomic deposits, shared budgets, unrepresentable delivery, 50 complete coupled steps with births, strict checkpoint continuation, duplicate composition, and simultaneous death/division into a reused slot. The sorption tests compare the closed-form law with the CPU oracle, including equilibrium, limiting cases, and conservative transfers at extreme inventory ratios.

This tranche proves the coupled law and checkpoint composition on a small native GPU fixture. It does not establish ecological selection, large-population throughput, or long-run mutation outcomes. Sustained runs must size cell capacity from all free/raw/bound/catalyst inventory and remaining external budgets. The helper borrows the base shared support descriptor and iterator for sensing and paid scatter; dense and optional axis support share one spatial law.

Strict restore validates every owned floating array, array role/type/shape, compensated-pair normalization and nonnegative physical ledgers/budgets, quota/mask totals, unused third feedstock species, catalyst capacity, and parameter types. Checkpoint creation applies the same host audit. Generic composition synchronizes a prior failure status before any sibling advances. These observation-boundary checks do not add per-step array downloads.

The final hardening gate passed all 20 independent restore/preflight/import-collapse assertions and 78 complete dense/axis coupling assertions, including strict axis checkpoint restore after 20 steps. This gate used the later shared-support source revision; its native AMD replay remains pending the next GPU window.
