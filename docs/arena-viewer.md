# Arena explorer

The arena explorer displays the runtime's actual `latest.json`: central 2D slices of the medium and projected agent positions. Field color is normalized to the current slice's measured range. Dot colors identify lineages. Clicking a dot opens the agent inspector, including whatever inherited policy and plastic controller state the runtime exports. Observed trails connect received snapshots, so they do not recover motion between publications.

Start the simulation, then serve it from a second terminal:

```sh
julia --project=. bin/interior.jl arena --continuous
python3 scripts/serve_arena.py
```

Both commands default to `outputs/arena/active-2d`; the local server defaults to port 8780. Start the runtime first because it claims ownership of its output directory. To serve another run, pass its directory to `serve_arena.py`. Resume an existing owned run with the runtime's `--resume` checkpoint option.

Open the URL printed by the server. The viewer polls once per second. It distinguishes a local runtime server from a static recording, and marks live snapshots stale if a running simulation stops advancing for twelve seconds. Paused simulations retain their explicit paused state. The Python server binds only to the loopback interface and accepts same-origin JSON controls.

Pause, resume, checkpoint, and parameter changes create an atomic `command.json` with a unique ID. The UI waits for the matching `control.json` acknowledgement before enabling another command. The gateway refuses to overwrite an unacknowledged command and appends accepted requests to `control-requests.jsonl`; the request log is separate from runtime acknowledgement. Requests rotate at 1 MiB into one previous log, limiting provenance storage to two files. Routine GET polling is not logged. Parameter bounds are checked both by this local gateway and by the runtime. An acknowledgement describes what the runtime accepted; it does not claim a future checkpoint already completed.

To publish an actual recorded snapshot without controls:

```sh
python3 scripts/build_arena_view.py outputs/my-arena
```

Copy `arena.html` and the recorded `latest.json` together into the curated collection. This works on static hosting; it shows **Recorded · snapshot**, and controls stay disabled. An optional `replay.json` containing an array of actual snapshots enables recorded playback and a frame slider. Rewinding clears observed trails and chart history. No trajectories or decorative agents are generated by the viewer. The chart only contains observations received since opening the page; its nutrient and population curves have independent scales.

## Snapshot contract

`schema` is `interior-arena-live`, `schema_version` is `1`; `grid` supplies `shape` and physical `extent`. Each `fields` entry has a two-dimensional `shape` and numeric `values` in x-fastest order. Agent entries supply `id`, `position`, `lineage`, `generation`, `energy`, and `storage`, plus optional inherited/plastic details. `step`, `time`, `paused`, and `metrics` describe the current runtime. The exporter atomically replaces this file so the browser cannot read a half-written snapshot.

## Cellular body view

Snapshots with `metrics.cellular_model` select the cellular rendering path. Each body uses its exported physical `radius` and the arena's physical extent; this is distinct from the fixed scientific markers used by the original and metabolic arenas. Bodies crossing a periodic boundary appear on both sides. In a 3D arena the map projects the bodies onto the central field slice rather than claiming to render sphere cross-sections.

The Medium, Cell bodies, and Bonds layers can be explored independently. Bond segments come from the exported stable-ID `cell_bonds` graph and use the shortest periodic displacement. Connected-component counts describe that graph; they do not designate organisms. Select an actual body to inspect internal precursor stocks, biomass, battery, ancestry, recurrent/adaptation state, and its eleven controller outputs. Neighbour buttons follow recorded bonds to other cells.

Cellular catalytic allocations are current controller outputs for precursor A uptake, precursor B uptake, growth, and oxidation. They are displayed separately from the inherited metabolic fractions of the older model. Battery and storage fractions appear only when the snapshot exports their capacities. Existing original/metabolic snapshots and recorded replays retain their own rendering and labels.
