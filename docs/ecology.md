# A finite evolutionary material ecology

`Ecology` is an optional CPU process. Founders carry individual recurrent controller matrices, hidden memory, energy, and material inventory. A persistent ID survives array reorder; offspring record parent, founder lineage, and generation. Hidden memory follows the moving carrier, and a newborn starts with its parent's current memory. Controller weights mutate only at successful reproduction. Birth-event seed, event count and parent ID determine a local RNG, so simulation steps do not consume an uncontrolled global RNG.

The controller observes nearest-cell nutrient, deposit, its own material and energy, and occupancy in a periodic 3×3 neighborhood at the same z slice. Hidden dynamics relax toward the recurrent tanh target with `1-exp(-dt/response_time)`, where `response_time` is a positive physical timescale (default 1). Small timesteps therefore refine the same memory dynamics instead of accelerating the controller clock. Its actions control physical movement, harvesting/secretion, and a splitting gate. This initial version does not implement architecture mutation, attraction, fighting or signaling. Three-dimensional movement is supported; neighborhood sensing remains planar and is recorded as such here.

## Economics and accounting

Material and work are distinct inventories. Initial grid nutrient plus deposit plus agent storage plus the explicit waste reservoir is the material ledger. Uptake transfers nutrient to storage; secretion transfers storage to enduring grid deposit; division splits storage equally; death returns storage to the occupied nutrient cell. No material is created by neural state changes. The waste reservoir is recorded but unused in this first policy.

A deliberately invented work model credits one abstract energy unit for every material unit harvested. Material remains stored: this represents an external chemical/light work subsidy coupled to harvesting, not mass-to-energy conversion. `energy_input` includes founders' initial energy and cumulative uptake credit. Basal maintenance and a shared active work budget deduct energy into cumulative `heat`. Movement and secretion receive the same funded fraction of that budget. Division requires twice the configured birth energy, dissipates one birth-energy unit into heat, then splits remaining energy. Death dissipates remaining energy. Thus total stored energy plus heat equals recorded energy input within floating-point error. Heat is an accounting reservoir, not a thermodynamic temperature field.

Agents exchange in ascending persistent-ID order. Local nutrient depletion therefore introduces a documented birth-order priority; it is reproducible under reorder but is not fair simultaneous allocation. This deserves replacement with a shared request allocation if ecological conclusions depend on crowding. Fixed capacity denies births without spending inventory, mutating weights, or incrementing birth events. Lifespan is an explicit model parameter rather than an evolved genome trait.

## Evidence and limits

`examples/ecology.jl` runs 240 founders on a finite 64×64 nutrient geography for 1,200 steps. It exports population and ledger diagnostics plus a shallow 64×64×8 extrusion of deposited material. The extrusion repeats a two-dimensional material field and is not a simulated three-dimensional ecology. The result can show inherited differential survival and generation turnover; it cannot establish open-ended complexity, adaptation, multicellularity or membrane function. Those claims require controls, perturbations, and functional measurements.

The relevant precedent is [Karl Sims' Evolving Virtual Creatures (1994)](https://www.karlsims.com/papers/siggraph94.pdf), where inheritable controller and morphology descriptions evolve in simulated physical worlds. Its explicit optimization and evolving morphology differ from this ecology's survival/reproduction competition and fixed carrier anatomy. Fraser Price's documented resource allocation and reproduction ideas are the closer visual motivation; see [the evidence notes](fraser-experiments.md). This code is a small independent implementation, not a reproduction of unavailable MOld source.

Tests check material and energy accounting, inheritance/mutation, reorder determinism, capacity refusal and death recycling. `record_process_fields` exports every persistent field, including effective weights and all ledgers; this observation format does not itself promise a restart checkpoint.
