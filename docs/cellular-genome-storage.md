# Indexed cellular genome storage

`CellularEcology(...; genome_storage=:indexed)` opts a new population into an owned, reusable genome bank. The default `:dense` representation remains available. Both representations execute the same controller, plasticity, inheritance and mutation equations, including the same mutation random-number order.

For a fresh arena recipe, set `genome_storage = "indexed"` in its `[cellular]` table. The existing arena constructor forwards this option; no benchmark-only conversion is needed. Keep the selected value in the saved recipe for reproducibility.

The common lifecycle path also reuses one batch-local Mersenne Twister generator, re-seeding it with the original daughter-specific string before every birth. This preserves uniform, Gaussian and placement streams while avoiding a fresh large generator allocation for each daughter. No generator is stored in the checkpoint or shared between populations. Focused tests compare mixed random streams after repeated re-seeding; complete historical trajectory comparisons remain the acceptance gate for this change.

The bank maps logical cell indices to physical genome slots. Birth copies its parent's contiguous weights and marks once; death releases a slot; population reordering changes the index map. Capacity grows geometrically. This removes population-wide genome copies during lifecycle events, at the cost of reserved capacity and indirection. Reserved memory is initialized, including newly grown tails.

`weights` and `plastic_marks` retain their three-dimensional logical array interface. Indexed arrays are owned live views: callers needing a stable snapshot should use `copy`, which materializes a dense array in logical cell order. Snapshot recording already materializes the values. Freed slots are inaccessible through logical indexing and are overwritten before a newborn uses them. Checkpointing preserves the shared bank and resource aliases; it also stores reserved capacity, so allocation savings do not imply smaller checkpoint files.

Actual old-baseline checkpoints were deserialized and validated under the widened field declarations before explicit indexed conversion. New indexed checkpoints have also passed strict restore and exact continuation tests. Existing immutable runs are not converted or resumed under changed source implicitly.

A checkpoint control at 2,139 cells occupied 19,021,668 bytes for dense storage and 29,747,638 bytes for indexed storage with capacity 4,096. Both strictly restored. Recorded write timings included first-call compilation and do not establish a write-speed comparison.

The focused test is `test/cellular_storage.jl`; it checks bitwise physical trajectories against the dense representation, birth/death/reordering, inactive-slot poisoning and reuse, neural parity, checkpoint continuation, and shared-bank ownership. Whole-step measurements and machine details are in `cellular-lifecycle-performance-results.json`.

On the controlled hbox CPU pair, the 1,489-cell birth-heavy case took 21.63 ms/step and allocated 7.65 MB, versus 22.37 ms/15.78 MB for the new dense representation. The 6,026-cell case took 95.37 ms/32.54 MB, versus the original f4 baseline's 101.23 ms/65.68 MB. These are modest whole-step timing improvements with approximately half the allocation, not a large accelerator speedup. Initial populations without immediate births had effectively unchanged timings. All four indexed cases passed exact 100-step physical-state and alias comparisons after materializing logical genome values; storage metadata was checked separately. After the largest replay reached 8,480 cells, active genome values occupied 46.40 MB while reserved genome buffers occupied 89.65 MB. Capacity and checkpoint costs matter when choosing the option.

The final combined candidate also includes the retained contact workspace, allocation-free neighbor hidden-state accumulation, and batch-local birth RNG reuse. A fresh matched-input 6,026-cell bracket measured **104.75 ms/step for f4 versus 93.03 ms for the combined candidate (1.126×)**, with allocation falling from **65.68 MB to 20.59 MB per step (68.6% less)**. The two later broadphase experiments were exact but did not improve complete-step time, so they were not selected. Five-second runs without artificial sleep sustained 8.02 versus 9.80 steps/s; because their populations grew to different sizes, these rates describe actual evolving runs and are not a fixed-work speed ratio. All selected physical changes passed exact 100-step trajectory and alias gates; the final RNG candidate was checked at both 1,489 and 6,026 starting cells.
